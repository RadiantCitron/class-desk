# class-desk 로컬 개발 환경 가이드

> **목적**: 로컬 머신에서 Docker와 Supabase CLI를 활용하여 `class-desk`를 실행하고 테스트하는 표준 가이드입니다.

---

## 1. 사전 요구사항

- **Node.js**: v22 이상 (`package.json`의 `engines`)
- **npm**: v10 이상
- **Docker Desktop**: 최신 버전 (PostgreSQL 및 Supabase 로컬 컨테이너 실행용)
- **Supabase CLI**: `npx supabase` 명령어로 자동 실행 가능

---

## 2. 로컬 실행 단계

### Step 1. 저장소 클론 및 패키지 설치
```bash
git clone https://github.com/RadiantCitron/class-desk.git
cd class-desk
npm ci
```

### Step 2. 로컬 Supabase 구동
Docker Desktop이 실행 중인 상태에서 아래 명령어를 실행합니다:
```bash
# 로컬 Supabase 컨테이너 시작 및 DB 마이그레이션 자동 적용
npx supabase start
```
처음 실행 시 PostgreSQL, Auth, Storage, Studio 등의 Docker 이미지를 내려받는 데 몇 분 소요될 수 있습니다.

### Step 3. 환경변수 설정
`npx supabase status`를 실행하여 로컬 인스턴스의 API URL 및 키를 확인합니다:
```bash
npx supabase status
```

출력된 키를 바탕으로 `.env.example`을 복사하여 `.env.local`을 작성합니다:
```bash
cp .env.example .env.local
```
- `NEXT_PUBLIC_SUPABASE_URL`: 보통 `http://127.0.0.1:54321`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`: `anon key` 출력값
- `SUPABASE_SERVICE_ROLE_KEY`: `service_role key` 출력값

### Step 4. 개발 서버 시작
```bash
# 개발 서버 실행
npm run dev

# 또는 가짜 PG 모의 서버와 함께 실행 (.env.test 필요: cp .env.test.example .env.test)
npm run dev:fake
```

브라우저에서 `http://127.0.0.1:3000`으로 접속합니다. (※ `localhost`가 아닌 `127.0.0.1`로 접속해야 쿠키 및 리다이렉트가 정확히 동작합니다.)

---

## 3. 테스트 스위트 실행

```bash
# 1. 타입 검사
npx tsc --noEmit

# 2. 단위 테스트 (Vitest, DB 불필요, 통합 테스트 제외)
npm test

# 3. 통합 테스트 (로컬 Supabase 필요)
npm run test:integration

# 4. DB 무결성·RLS 검증 SQL (로컬 Supabase 필요, 실행 후 롤백되어 흔적을 남기지 않음)
docker exec -i supabase_db_class-desk psql -U postgres -d postgres < supabase/tests/integrity_check.sql
docker exec -i supabase_db_class-desk psql -U postgres -d postgres < supabase/tests/rls_check.sql

# 5. Playwright E2E (로컬 Supabase 필요, .env.test 필요)
npm run e2e
```

`.env.test`는 `.env.test.example`을 복사해 Supabase 키만 채우면 됩니다. 모든 결제 주소는 로컬 가짜 PG(`tools/fake-pg`)를 가리킵니다.

---

## 4. 로컬 Supabase 중지 및 초기화

```bash
# 컨테이너 일시 중지 (데이터 유지)
npx supabase stop

# 컨테이너 및 데이터 완전 초기화 후 재시작
npx supabase db reset
```
